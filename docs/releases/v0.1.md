# v0.1 快速发布方案：纯 BM25 Skill Registry

**状态：已收敛实现范围。** v0.1 是单进程、本地 SQLite + local-fs 的权限化 Skill Registry。它只承诺稳定的 BM25 `skill_search`、同步导入、版本回滚、缓存、RBAC 和 stdio/SSE/Streamable HTTP MCP transport。

## 发布范围

| 保留 | 说明 |
| --- | --- |
| `skill_search` | 内存 BM25 索引覆盖 Skill 的名称、描述、`triggers`、`when_to_use` 与 `embedding_text`。先计算 RBAC 可见候选集，再计分、排序和截断，避免私有高分结果挤掉可见结果。C2 代理模式下搜索代理到 storage 的 gateway 搜索端点，BM25 仍由 storage 本地评分。 |
| 本地数据 | SQLite 元数据、local-fs Skill 文件、版本快照、回滚、缓存 epoch、审计和 access log。 |
| 导入 | 本地目录与 Git URL 的同步导入、manifest/path 校验、注入扫描、内容哈希与版本快照。 |
| 权限 | JWT 管理、Bearer Token MCP/Gateway 读取，以及 tag 可见性过滤。 |
| transport | stdio；Streamable HTTP `/mcp`；SSE `/mcp/sse` 和 `/mcp/messages`；本地 Admin/Gateway HTTP API。 |
| 运行保障 | `/api/health`、限流、结构化日志和经鉴权的 Prometheus `/metrics`。 |
| C2 远程代理 | 通过 `CLOUD_SERVICE_URL` 启用：`serve` 构造 `RemoteSkillProvider` 将 skill 读取代理到远程 storage Registry；`skill_search` 代理到 storage 的 gateway 搜索端点（BM25+RBAC 在 storage 侧）。推荐 `MCP_ONLY_MODE=true` 配合使用。详见 `docker/docker-compose.yml` c2 profile。

## 明确移除

以下能力没有运行时模块、CLI 命令、HTTP/MCP 路由、配置开关或 npm 依赖：向量/embedding/混合检索、Eval、Pipeline、OSS、Webhook、异步导入、Usage ledger、OpenTelemetry、自升级和 PostgreSQL。

`embedding_text` 是历史字段名，继续作为普通 BM25 语料；不会生成向量或发起模型网络请求。为避免旧 MCP 客户端校验失败，`skill_search` 可兼容接受旧 `mode`、`hybridAlpha` 参数，但它们不会出现在工具说明中且会被忽略，结果始终由 BM25 产生。

## 支持的部署方式

- **A：本地 stdio**：个人 IDE/Agent 使用本地 SQLite 和文件目录。
- **C1：单机 HTTP**：同一进程承载 Streamable HTTP、SSE、Admin/Gateway API、SQLite、local-fs 和 BM25 索引；这是唯一支持的共享/生产拓扑。
- **C2：分布式代理**：通过 `CLOUD_SERVICE_URL` 将 storage（API-only，权威本地方案）与 mcp1/mcp2（MCP-only，RemoteSkillProvider 代理）分离。storage 负责拥有 BM25 索引、RBAC 与数据；mcp 节点代理所有 skill 读取与搜索。通过 docker compose `--profile c2` 部署。
- **MCP-only/API-only**：C1 的受限 route 模式，不是远程 Proxy。MCP-only 用于已预置数据的只读 MCP；API-only 用于管理自动化或作为 C2 中的 storage 侧节点。

v0.1 不支持横向扩展同一个 SQLite 实例。`--server-url`/`SKILL_MCP_SERVER_URL` 只用于管理 CLI 请求另一台独立的 v0.1 Registry——不解释为服务端代理（服务端代理由 `CLOUD_SERVICE_URL` + `RemoteSkillProvider` 实现，见上方 C2 场景）。

## 稳定搜索契约

1. `serve` 在接受任意 MCP/HTTP 请求前 `await` 完整 BM25 索引水合；首建失败会阻止服务启动。
2. 导入成功返回前会等待对应 Skill 的索引刷新；事件订阅继续为更新/删除提供增量收敛。
3. `skill_search` 返回的所有 Skill 都已经过生命周期和 RBAC/tag 过滤。BM25 索引接收授权 ID 集合，在评分前过滤候选而非在全局 top-N 后过滤。
4. 推荐所有首发 Skill 编写准确 `description`，并提供 `triggers` 与 `when_to_use`。`embedding_text` 可补充关键词与同义表达，但内容按普通检索文本审核。

示例：

```yaml
---
name: web-access
description: Access web pages and extract content.
triggers: [visit page, open link, extract web content]
when_to_use: Use when a user asks to access, read, extract, or interact with a web page.
embedding_text: Browser navigation, web page content extraction, and link interaction.
---
```

## 数据库兼容性

不修改 `drizzle/0000_baseline.sql` 或历史 migration；`src/db/schema.ts` 中 `import_jobs`、`usage_events`、`pipeline_runs`、`webhooks`、`webhook_deliveries`、`skill_eval_cases`、`skill_eval_runs` 和 `skill_embeddings` 表声明仅作为 **compatibility-only tombstone** 保留。它们没有 v0.1 repository 或运行时写入路径，且不得生成 DROP migration。

对没有 `__drizzle_migrations` 账本的非空 legacy SQLite 文件，v0.1 迁移会 **fail closed**：不执行 `DROP TABLE`、不修改数据，并要求先备份后使用经审查的显式原位迁移。这样优先保证不删库、不丢失 Skill、用户、角色和版本数据。

`DATABASE_URL` 与非 `local-fs` `STORAGE_TYPE` 会在启动前给出明确错误；不会静默回退到空本地目录。`CLOUD_SERVICE_URL` 不再报错——它启用 C2 远程代理（见上方「保留」）。

## 发布验收

```bash
npm run build
npm run lint
npm test
npm run docs:sync
git diff --check
```

还需人工 smoke：初始化 Registry，导入一个包含检索字段的 Skill，使用授权和未授权 token 分别调用 `skill_search`，确认导入后立即可搜索、私有 Skill 不泄露；分别验证 stdio、`/mcp`、`/mcp/sse`，以及 `versions`/`rollback`。

## post-v0.1 路线

未来若恢复向量或远程存储，必须作为新的、独立验收的功能：定义持久化 vector store、历史回填/删除/版本收敛、权限感知查询、可观测的错误语义和端到端 migration。不得仅通过重新暴露旧配置或 MCP 参数启用。
