Skill MCP Server

云端技能文件系统 + MCP 权限网关 · 让 AI 助手按需加载可复用的"技能包"

v0.1.1-beta.0 TypeScript · ESM · Node ≥22 MCP SDK SQLite + Drizzle stdio / HTTP / SSE 743 tests passed
⌨️ 1-0 / Esc

?它做什么

把可复用的"技能包"（一份带 SKILL.md 主文件 + 可选辅助文件的目录）变成 AI 助手按需加载的资源。

  • 导入 / 版本化 / 回滚 技能
  • 通过 MCP 协议把技能开放给任何 MCP 客户端（Claude Code / Cursor / 自研 Agent）
  • 多租户：同一服务给不同用户呈现不同的可见技能集
  • 流水线：把多个技能编排成 DAG 并发执行

!解决什么痛点

大模型上下文窗口有限，把所有"领域操作手册"塞进系统提示词既贵又脏。本服务提供：

  • 按需加载——只在触发时把相关 SKILL.md 推给模型
  • 权限隔离——按用户/角色/标签过滤可见技能
  • 安全——导入时做 prompt 注入扫描、路径穿越防护
  • 缓存——L1 内存 LRU + L2 文件双层，热路径毫秒级

skill_list必检
列出当前调用方可见的所有技能

每次会话开头由 LLM 调用，返回经 TagPermissionFilter 过滤后的技能目录。 匿名调用方仅能看到 visibility=public 的技能；持有 token 的调用方按角色 tag 交集过滤。

入参
tags?: string[] · 按能力标签过滤
返回
文本格式：- slug [id:uuid]: 描述
// 不带过滤
skill_list({})

// 按 tag 过滤
skill_list({ tags: ["code-review"] })
skill_view入口
加载指定技能的完整 SKILL.md 指令

唯一的"开始用某技能"入口。返回的文本就是该技能的工作指令，LLM 后续行为由它驱动。

入参
skill_slug?: string 或 skill_id?: string（二选一）
权限
不可见的技能返回 Permission denied
skill_view({ skill_slug: "product-analyzer" })
skill_file辅助
批量读取技能包内的辅助文件（参考、模板、脚本）

仅当 SKILL.md 显式引用某文件时调用；图片/视频以 base64 返回。 数组并发读取，减少 LLM 与服务的 round-trip。 

skill_file({
  skill_slug: "product-analyzer",
  file_paths: ["references/api.md", "templates/checklist.md"]
})
skill_pipeline编排
按 DAG 编排多个技能并发执行

支持新建 / 暂停恢复（断点续跑）。阶段间通过 ${{ stages.x.outputs.y }} 表达式传值。 

# YAML 流水线定义
name: code-review
stages:
  fetch:
    skill: github-pr-reader
  security:
    skill: security-scanner
    depends_on: [fetch]
    inputs:
      code: ${{ stages.fetch.outputs.diff }}
skill_feedback反馈
技能使用完毕后回报效果，用于推荐排序优化
skill_feedback({
  skill_slug: "product-analyzer",
  outcome: "success",           // success | partial | failure | irrelevant
  context: "分析了商品缓存不一致",
  agent_comment: "步骤清晰,成功定位问题"
})

一次 skill_view 调用走完的完整链路（点击查看每步细节）↓

1

请求进入

客户端（Claude Code / curl / SDK）发起 MCP 请求，带 Bearer token。

2

鉴权 & 上下文构建

ContextBuilder 把 token 解析成 RequestContext（含 userId、tags、isAuthenticated）。

3

MCP 路由

SDK 根据 method 派发到 skill_view handler。

4

权限过滤 & 缓存查询

L1 内存 LRU → L2 文件 → 不命中则进 Provider。

5

Provider 取数据

本地或远程，对上层透明。

6

裁剪 & 回写缓存

命中后下次毫秒级返回。

设计原则：每一层只对上一层负责，事件驱动失效缓存（DomainEventBus → CacheSubscriber → epoch bump）。

同一份二进制，4 种部署形态，由 DEPLOYMENT_MODE + TRANSPORT_TYPE 切换：

典型场景一览

场景模式传输用途
Astandalonestdio本地开发
Bgatewaystdio本地代理 + 远端服务
C1standalonehttp单机统一 HTTP
C2gatewayhttp分布式生产

从客户端 token 到可见技能集，鉴权链路只有三步：

UUser

由 skill-mcp user create 生成。token 形如 sk-live-xxx，落库前 SHA-256 哈希，仅明文一次。

RRole

由 skill-mcp role create 生成，每个 Role 携带一组 tags（即权限标签）。

FTag Filter

对每条 skill 计算 user.tags ∩ skill.tags。空交集 = 不可见。visibility=public 跳过过滤。

# 一个完整的鉴权配置示例
$ skill-mcp role create --name dev --tags team-alpha,code-review
Role created: id=fc3e... tags=[team-alpha, code-review]

$ skill-mcp user create --name alice --role-ids fc3e...
User created: token=sk-live-afae31a4...
⚠ token 仅展示一次

# 调用时
$ curl -H "Authorization: Bearer sk-live-afae31a4..." http://srv/api/gateway/skills

能见度规则

visibility匿名已鉴权 + tag 不交集已鉴权 + tag 交集
public⚠ 仍需 401（gateway 强制鉴权）✅ 可见✅ 可见
internal❌✅ 可见✅ 可见
private 默认❌❌ 不可见✅ 可见

📐 限制 & 安全

  • 仅接受文本文件（isTextFile() 白名单：md / txt / json / yaml / py / js / ts / sh / …）
  • 路径走 safeJoin 拒绝 .. 与符号链接，最大深度 16 层 / 1000 文件 / 50MB 总大小
  • 所有文本均经 scanForInjection（命中 <system>、ignore previous instructions 等模式直接拒绝）
  • 导入采用 staging-commit：写到 __staging__/<runId>/ → DB 落库 → 原子 moveDir 提交，失败可逆

🔄 双层缓存（L1 内存 LRU + L2 文件）

L1 LRU 1000 条默认上限；L2 文件缓存带 TTL 倍增因子（默认 2x）。事件驱动失效：当 skill 被更新时 publish skill:updated，CacheSubscriber 收到事件后按 visibility 决定 global epoch bump 或 per-user epoch bump，O(1) 失效。

📦 Staging-Commit 导入流程

导入路径采用先写 staging（__staging__/<runId>/），DB 写完再原子 moveDir 提交。失败时按"DB 反向补偿 → 回滚 finalPath（仅 created）→ 永远清理 staging"恢复。并发导入靠 randomUUID 隔离。

🛡️ 安全扫描

导入时对所有文本文件做 prompt injection 扫描（scanForInjection），命中可疑模式直接拒绝。manifest 走 safeJoin + symlink skip + 深度 16 / 1000 文件 / 50MB 上限，防路径穿越和 zip-bomb 类滥用。

🌐 三种 MCP 传输

stdio：本地子进程，token 由 --auth-token 注入；Streamable HTTP /mcp：单端点，每会话一个 transport instance；SSE /mcp/sse + /mcp/messages：SDK 兼容老协议。两条 HTTP 路径都通过 attachMcpAuthFromHeaders 把 Authorization 头桥接进 RequestContext。

📊 可观测性

Prometheus 指标覆盖 cache / db / provider / tool / pipeline / 安全策略命中等。/metrics 默认走 enforceAdminAuth，可通过 SKILL_MCP_METRICS_AUTH_OPTIONAL 打开内网 Prometheus 抓取。

🔁 流水线引擎

YAML 定义 DAG，DAGScheduler 按拓扑批次推进，同批内 Promise.all 并发；PipelineRunStore 内存 + DB 双写，崩溃后按 inputs + completedStages 重放重建 ExecutionContext，支持暂停/恢复（人工补全外部输出再 resume）。

🧪 测试覆盖

93 测试文件 / 743 测试通过。包含：单元（service/provider/cache/permission/repository/handler），集成（scenario A/B 用 spawn 真实进程），E2E（scenario C 多容器）。MCP 鉴权直通、initialize.instructions 不泄露私有元数据等都有黑盒回归。

📜 版本化 & 回滚

每次 import 触发 content-hash 比对决定是否新增版本；skill_versions 表保留全部历史。回滚走 staging-commit：目标版本先落 staging → 按文件覆盖 live → DB 切版 → 缓存失效；失败按 pre-rollback snapshot 反向恢复。
